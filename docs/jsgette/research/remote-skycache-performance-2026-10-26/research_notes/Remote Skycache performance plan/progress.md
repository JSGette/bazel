# Current SkyCache implementation and performance evidence

## What is implemented and what was actually measured?

### Takeaway
The earlier 256 MiB/562-test status is obsolete. The current remote branch has 4 GiB logical publication support, authenticated 4 KiB cached reads, bounded concurrency 100, shorter sealed-bucket locks, and persistent verified remote chunks. The latest measured workload still loses to local SkyCache and vanilla Bazel, even when blob downloads fall to zero. [Current protocol](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-cache-protocol-2026-10-25.md#L282-L338)

- Cold remote consumes 1,462,361,840 blob bytes in 1,604 chunks. All six warm remote samples consume zero blob bytes/zero blobs and reuse the same 1,604 chunks. Warm nevertheless receives 5,551–5,633 wire bytes and sends 10,258,254–10,259,080 wire bytes on the metadata proxy: catalog discovery, protocol traffic and publication uploads remain. Twelve of twelve remote samples commit a publication, with 5–16 new private writes and both parent descriptors reused. [Transfers/commits](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L905-L944)
- Cold and warm share a frozen publication with local within the matrix. Warm seeds contain only the chunk subtree, copied into a separate private cache for each invocation; no local publications/leases/locks are seeded. Every sample uses a fresh JVM and clean graph/action state; build wall time excludes startup, clean, seed-copying and one backend warmup, but includes publication. Backend CAS/OS caches are warm; metadata backend is loopback, without WAN shaping. Ordinary action-cache connections use the common 16-requests-per-connection override. [Controls](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L886-L903)
- Publication is synchronous: `LocalSkycacheModule.afterCommand` calls `session.finish`, which calls `remote.publishPending`; export performs blocking uploads followed by blocking commit. Thus the residual warm/local wall-time difference includes publication and cannot be entirely assigned to validation or reads. [afterCommand](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/LocalSkycacheModule.java#L258-L285); [finish](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/LocalCacheSession.java#L839-L903); [upload/commit](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L1004-L1055)
- Latest matrix explicitly uses `--experimental_remote_skycache_max_transfer_size=2G` and `--experimental_remote_skycache_timeout=600s`. Defaults remain attempted blob budget 257 MiB and aggregate active read-RPC time 60 s; export uses one absolute 60 s deadline. Failed attempts consume budget, overlapping calls each charge active time, catalog payloads do not consume blob-byte budget. Logical closure independently allows 4 GiB. Raising the logical limit did not make the 1.46 GB cold reader succeed with default transfer settings. [Harness](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/harness/benchmark_agent_retained_matrix.py#L629-L637); [budget semantics](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-cache-protocol-2026-10-25.md#L282-L298)
- Historical improvements are real engineering progress, with caveats: minimal remote 457.71 s (one sample) →93.68 s (block authentication n=3) →85.08 s (overlap n=3) →56.78 s (concurrency n=3) →45.97 s (latest empty-cache n=3). These are successive equivalent workloads with separately primed seeds because binary installation identity versions analysis keys; not one controlled A/B test across identical bytes. Latest warm 26.17 s has no historical warm-arm comparator. [Historical sequence](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L572-L884)

### Inferences
- Current priority is reducing total reuse overhead and cold transfer amplification, not raising concurrency again or reimplementing retention/block authentication. Observed latest cold peaks are only 29–32 downloads, cached-reader peaks 27–34 under cap 100. Authentication cache peaks at 11,636,640 B with zero evictions, so raising its 32 MiB limit is not supported by this fixture. [Observed counters](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L922-L944)
- Warm remote is about 1.96× vanilla in minimal and 1.32× in toplevel, calculated from the reported medians; reaching zero download bytes alone is insufficient. These descriptive ratios do not isolate causality. [Same-matrix source values](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L865-L884)

### Gaps
- No independent-machine/WAN result, no cold OS-storage test, no production cache-server interoperability, no sustained multi-client/eviction-pressure result. Latest n=3 cells cannot establish p95/p99 or small effects. [Explicit limitations](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L953-L961)
- No new tests, builds or benchmarks were run for this audit. Existing evidence was read only.

## Which source hotspots justify the next experiments?

### Takeaway
The best-supported immediate work is instrumenting end-to-end reuse costs, separating publication from consumption, checking CAS presence before bounded upload batches, and then measuring smaller demand-transfer units. Warm reads also still allocate/read/hash repeatedly; algorithmic validator changes require proof and phase attribution before selection. [Current remaining work](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L1016-L1050)

### Cited Findings
- **Upload path is sequential singleton batching:** `RemoteSkyCache.uploadLocal` allocates up to 1 MiB per chunk and immediately calls `transport.upload` in nested file/chunk loops. `SkyCacheTransport.upload` creates a single-request `BatchUpdateBlobs`; no `FindMissingBlobs` call exists in this SkyCache path. Commit uploads the bundle then invokes the catalog. Source supports batching/dedup opportunity but does not quantify its wall-time share. [RemoteSkyCache.java:1004](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L1004-L1055); [SkyCacheTransport.java:325](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/remote/SkyCacheTransport.java#L325-L361)
- **Demand path has 1 MiB transfer granularity:** `SkyCacheProtocol.CHUNK_BYTES=1024*1024`; download uses ByteStream from offset zero with whole-digest verification. Cold latest downloads ~1.462 GB, while returning ~244.62 MB of shared values (about 5.98×, different byte categories; not an estimate of all necessary metadata). [Protocol constants](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/remote/SkyCacheProtocol.java#L17-L21); [download](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/remote/SkyCacheTransport.java#L364-L395); [raw comparison](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/comparison.json)
- **Cached range reads still perform per-read filesystem/allocator/hash work:** `readCachedBytes` allocates a buffer, opens FileChannel, checks size, positional-reads, checks size and closes; `readCachedRange` reads whole covering 4 KiB blocks and hashes each, with `blockDigest` creating a SHA-256 MessageDigest each time. A hash-cache miss reauthenticates the entire chunk. No payload caching is implied by the block-hash cache. [RemoteSkyCache.java:222](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L222-L349)
- **Retained activation verifies full chunks each invocation:** `reuseRetainedChunk` privately links a chunk, reads full declared length+1, verifies digest, derives block hashes, links final name and touches last-use time. This is intentional correctness behavior; an optimization must preserve authenticated returned bytes and mutation handling. [RemoteSkyCache.java:454](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L452-L500)
- **Latest validation workload remains large:** raw rows contain approximately 790,700 CAS get requests and 244,619,755–244,619,823 value bytes; local sample rows show 603,428 dependency records read, 182,455 witnesses checked, 305,730 witness memo hits and 249,870 admission-witness memo hits. Warm remote cached-range bytes are ~3,542,967,423–3,542,983,807 (around 14.5× returned values; not total process reads). These counts motivate locality/validation/decoder profiling, not a claim that validation is the primary bottleneck. [Raw rows](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/comparison.json)
- **Validator already does invocation-local DAG sharing:** `validate` memoizes successful roots, uses per-root locking; iterative DFS defers shared in-flight dependencies to do independent work first; witness reuse remains invocation-local; final publication revalidates content; no negative result persists. Do not propose these as new mechanisms. [LocalDependencyValidator.java:124](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/LocalDependencyValidator.java#L124-L250)
- **Sealed-bucket lock shortening is implemented:** `findForRead` skips bucket monitor when sealed; segment index opening has a per-segment lock, verifies index digest, and caches open store. Segment search remains reverse sequential; unavailable newer matching data must stop fallback, otherwise an older differing value might be selected. [SegmentedFingerprintValueStore.java:300](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/SegmentedFingerprintValueStore.java#L300-L374)
- **Preparation still eagerly authenticates admission data for one discovery page:** `prepareExclusive` calls discover with empty page token, reads bundle, manifests, all global witness blocks and root indexes; segment data remains demand-read. [RemoteSkyCache.java:710](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L710-L783)

Absolute local evidence/code root is `\\wsl.localhost\Ubuntu\home\jgett\REPOS\bazel-skycache-remote-mvp`. Append paths above; link line numbers refer to inspected HEAD. Highest-value report links: `docs/jsgette/skycache-remote-mvp.md:845`, `:886`, `:905`, `:953`; `src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java:222`, `:454`, `:1004`; `.../remote/SkyCacheTransport.java:325`; `.../local/LocalDependencyValidator.java:124`.

### Inferences
- Measure wait time separately from service time for download slots, transport slots, per-chunk locks, segment opening and validator waits. Add explicit preparation, reuse/validation, retained activation, serialization, missing-blob lookup, upload and commit spans. Existing aggregate cached-read/RPC durations overlap and must not be subtracted from build wall time or summed as exclusive phases. [Counter caveat](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L914-L920)
- Compare bounded FileChannel/descriptor reuse, buffer reuse, digest-instance reuse and authenticated immutable payload/block caching only after allocation/syscall/CPU profiles rank them. Retaining unverified mutable byte mappings or skipping hash checks would violate current semantics. The raw count of ~790k gets makes per-read overhead plausible; no claimed speedup yet. [Current read contract](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L282-L309)
- Use a same-revision factorial experiment: consumption-only versus normal publication; cold/retained warm; fixed 1 MiB/256 KiB; dedup only/batching only/both. Compare net command wall time plus byte/RPC/CPU/memory counts, with unchanged subtree and changed subtree controls. This is a proposed plan inferred from current confounding and the implementation seams, not an existing result. [Existing limitation and planned candidates](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L531-L559)

### Gaps
- No exclusive timing proves how much of residual warm overhead is publication, filesystem work, validation, deserialization or scheduling. Need a controlled next experiment, not attribution by subtracting independent medians. [Counter semantics](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L914-L920)
- No evidence that increasing max concurrency beyond 100 or hash-cache budget beyond 32 MiB improves this fixture; no evidence that current production data favors CDC. [Observed peaks](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L937-L961)

## Which tempting alternatives are premature or already answered?

### Takeaway
CDC has already been tested offline and did not save realistic delta bytes in the available small corpus. Stable identity, selective external witnesses and production catalog access/retention remain separate capability gaps, not proven ways to accelerate the current same-clone loopback workload. [CDC results](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L974-L1050)

### Cited Findings
- Existing CDC experiment: 108 distinct actual packs, 38,361,013 bytes; fixed 1 MiB/256 KiB/64 KiB and FastCDC averages 256 KiB/64 KiB all needed exactly the same new pack bytes across three repetitions. Fixed-1-MiB chunk+SHA median 14.60 ms versus CDC-256-KiB 24.82 ms; C/Python warm-memory timings are not Java build latency. Synthetic one-byte insertion favored CDC (319,696 vs 1,498,290 new bytes), demonstrating resynchronization, not a real build benefit. [CDC evidence](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L983-L1014)
- Reader allows variable chunks, but max chunk is 1 MiB and bundle 1 MiB; standard REAPI FastCDC max=4×average implies max average 256 KiB within current chunk limit. Smaller chunks increase descriptor/RPC counts; a multi-GiB 64-KiB experiment can require a separately bounded descriptor layout. [Constraints](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L554-L559); [CDC profile](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L976-L981)
- Current catalog client consumes one bounded discovery page. Future lazy pagination and ranking by target/configuration hints must still honor scan/network/metadata budgets and per-entry validation. Independent clones require explicit stable repository identity, not just namespace override; external witness guards remain global/conservative pending equivalent proof. [Remaining compatibility work](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L1033-L1044)
- Development worker serves trusted producers; CAS shares instance namespaces; namespace is not authorization, and digest authenticity is not producer honesty. Production capability negotiation, authentication integration, catalog retention/replication and CAS leases are unresolved. [Deployment profile](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-cache-protocol-2026-10-25.md#L300-L350)

### Inferences
- Keep CDC behind a realistic large-record-change/compaction/repacking trace experiment, comparing equal average chunk sizes, total CPU and request costs. Prioritize skipping existing uploads and fixed smaller chunks first. [Existing measured rationale](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L995-L1007)
- Treat independent-clone identity as a prerequisite for eventual remote deployment evaluation, but keep it separate from optimization A/Bs so performance results are not confounded by changed compatibility keys. Never weaken install identity merely to manufacture cross-binary hits. [Identity control](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L566-L570)

### Gaps
- Seven extracted draft PRs are tracked separately by the coordinator; this audit did not inspect their live GitHub state. Their existence must not be counted as delivery of remote performance work.
- No user-authorized implementation was performed. This file contains evidence and proposed experiments only.
