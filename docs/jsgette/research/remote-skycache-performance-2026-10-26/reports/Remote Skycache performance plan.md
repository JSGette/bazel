# Make remote SkyCache faster through measurement

**26 October preliminary measurements update:** [The follow-up investigation](Remote%20Skycache%20preliminary%20findings.md) moves publication preparation ahead of upload batching. Valid retained-remote runs spent about six seconds before their first upload, while upload through commit took only 0.36–0.40 seconds. All 103 newly written witness blocks were identical to parent blocks. The original research and experimental options below remain useful; the follow-up supplies the current evidence-based ordering.

**Prioritize attribution, then bounded publication batching and cheaper authenticated reads; defer new certificate machinery until profiles justify it.** Remote SkyCache now handles the large Datadog publication and retains verified chunks, but its latest retained-cache medians remain **26.17 versus 14.27 seconds locally** with minimal outputs, and **33.78 versus 25.22 seconds locally** with top-level outputs. Those remote runs download zero blob payload bytes, so eliminating downloads alone does not close the gap. Their timed commands still include publication, initial verification of retained chunks, local reads, validation and restoration. Recent 2026 research strengthens the case for measuring hit-processing costs and complete dependency observations before changing cache algorithms. This report reviews the evidence available **26 October 2026** and specifies experiments, correctness constraints and promotion gates. It is a plan only: no implementation, builds, benchmarks, network changes or service changes were performed for this review. ([Latest measurements](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L845-L961))

## Progress is substantial, but zero downloads still leaves a gap

The current remote checkout is clean at **`bf6b717195`**. The latest measured product revision is **`b368beb0ddde51434ce20c063546047ecccb2a88`**; subsequent changes are token-preserving Java formatting/comments and documentation. The audit found no runtime change, but the measurements are not a fresh run of HEAD. The previous 256 MiB publication limit and 562-test snapshot are superseded: logical publication closure now supports **4 GiB**, and the latest evidence records **612 passing test cases across 22 selected test targets**, not the full Bazel suite. Authenticated 4 KiB reads, overlapping downloads/reads, concurrency capped at 100, sealed-bucket lock shortening, shared download coordination and persistent chunks are already implemented. ([Provenance](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/verification.json), [formatting verification](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/formatting.json))

The latest matrix contains **24 timed builds: three repetitions × four arms × two output policies**. All cache readers restored 17 configured-target and 11 execution entries; six output digests matched vanilla, with downloaded-file hashes additionally checked for top-level outputs. ([Experiment record](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L845-L884))

| Output policy | Vanilla median | Local SkyCache | Remote, empty retained cache | Remote, retained chunks |
|---|---:|---:|---:|---:|
| Minimal | 13.32 s | 14.27 s | 45.97 s | 26.17 s |
| Top-level | 25.63 s | 25.22 s | 54.43 s | 33.78 s |

**Every cell has only three observations.** These are descriptive results, insufficient for reliable tail estimates or small-effect claims. Each sample starts a fresh JVM with clean graph/action state. Startup, cleaning and seed copying are excluded; publication is included. Retained seeds contain only chunks, with a separate private cache per invocation. Backend CAS/OS caches are warm, and the metadata service is loopback without WAN shaping. “Empty retained cache” therefore does not mean every storage layer is cold. ([Controls and limits](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L886-L961))

Cold readers fetch **1,462,361,840 bytes across 1,604 chunks**. All six retained-warm runs fetch zero blob bytes, but still upload approximately **10.26 MB** and commit publications containing 5–16 private writes. The aggregate cold-blob/value-byte ratio is approximately **5.98×**; authenticated range bytes/value bytes are approximately **14.5×**. These compare different byte categories, include repeated/block-aligned work and are not measurements of wholly unnecessary traffic. Distinct demanded bytes must be measured before assigning waste. ([Raw results](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/comparison.json))

The matrix uses **2 GiB transfer and 600-second timeout overrides**. Defaults remain **257 MiB attempted blob bytes and 60 seconds aggregate active read-RPC time**; overlapping reads each consume that time budget, while export has an absolute deadline. These limits are independent of the 4 GiB logical closure. The demonstrated 1.46 GB cold read does not establish success under defaults. Observed download peaks of 29–32 and cached-reader peaks of 27–34 do not support raising the existing cap of 100. Authentication metadata peaks around 11.64 MB with **zero evictions**, so enlarging its 32 MiB cache is also unsupported. ([Budget semantics](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-cache-protocol-2026-10-25.md#L282-L298), [observed counters](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L922-L944))

## P0 must identify the critical path before choosing a mechanism

The first experiment should separate **consume-only diagnostic runs from normal consume-plus-publish runs**, using one binary, one frozen publication and identical source state. `LocalSkycacheModule.afterCommand → LocalCacheSession.finish → RemoteSkyCache.publishPending` makes publication synchronous. The diagnostic split measures its cost; it does not propose silently abandoning publication guarantees. Repeat with empty and retained chunk caches, unchanged inputs and a controlled changed subtree. Include native defaults alongside the research overrides, recording budget exhaustion and conservative fallback as outcomes. ([Publication call chain](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/LocalCacheSession.java#L839-L903))

Plan spans for discovery/preparation, retained activation/full verification, range reads/hashes, witness observation, dependency validation, deserialization, graph insertion, serialization, uploads, commit and cleanup. Separate service from waiting on download slots, transport slots, chunk coordination, segment opening and validator coordination. Collect CPU, allocation, filesystem operations, read bytes, unique chunks/blocks, memo occupancy and lock contention. Attribute wall time using interval overlap and dependency traces: **summing thread durations does not reconstruct the critical path**, and subtracting independent arm medians does not isolate validation. Promote P0 only when repeated traces identify a dominant actionable cost with sufficiently small unexplained residual to choose the next experiment.

This priority follows recent research rather than hit-rate intuition. Qiu, Yang and Harchol-Balter's **peer-reviewed April 2026** queueing study shows that hit-path maintenance contention can lower throughput even as hit ratio rises. Its closed-system model is not a diagnosis of SkyCache, but it directly motivates examining synchronized cache hits and verification work. The **PVLDB 19(4)/VLDB 2026** lazy-promotion study similarly finds value in reducing cache-maintenance operations. Neither justifies replacing our policy before observing contention. ([Queueing study](https://link.springer.com/article/10.1007/s11134-026-09986-1), [lazy-promotion paper](https://arxiv.org/html/2608.29993v1))

Use balanced randomized paired blocks, initially about ten pairs for decisive comparisons, extending only when uncertainty overlaps the predeclared practical threshold. Preserve raw runs and paired uncertainty intervals. Start with fresh JVM/clean graph states; then separately test retained chunks with cold versus warm OS caches, warm process/idle recovery and backend cache states. Hold binary hash, namespace, target set, output policy, ordinary action/output-cache state, budgets and machine resources fixed. Use a code-identical cache-off baseline plus local, remote and vanilla comparators. Do not alter installation identity to manufacture cross-binary hits. Build-level p95/p99 needs substantially more independent builds than this initial experiment; numerous RPC samples do not substitute for them.

Promotion should require verified outputs, unchanged fallback semantics, bounded memory and a useful end-to-end improvement whose paired interval excludes no improvement. **A provisional target is at least 5% improvement in the target arm with no more than 3% regression in protected arms**, finalized after P0 variance and product requirements are known. These are proposed decision thresholds, not predicted gains. Amdahl's bound, `speedup ≤ 1 / ((1 − f) + f/s)`, constrains expectations when an improved stage occupies fraction `f` and accelerates by `s`; new overhead and overlap can reduce the realized benefit further.

## P1 should test publication and authenticated-read costs separately

**Publication is the first narrow implementation candidate, unless P0 shows a materially larger read-path opportunity.** `RemoteSkyCache.uploadLocal` currently walks chunks sequentially and awaits each upload; `SkyCacheTransport.upload` sends a singleton `BatchUpdateBlobs` request. No `FindMissingBlobs` call exists in this path. Compare current behavior, bounded batching alone, presence checking alone, then their combination. Use unchanged and changed publications, including small publications where an extra lookup can lose. This is an implementation-ready seam with an independently measurable outcome: commit-inclusive command latency, uploaded bytes, RPC counts, CPU and peak bytes in flight. ([Producer loop](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L1004-L1055), [transport](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/remote/SkyCacheTransport.java#L325-L361))

For serialized calls, a useful first model is `T ≈ N·RTT + U/B + CPU + commit`, with `N` requests, `U` bytes and bandwidth `B`; measure overlap before using it to predict wall time. Batching reduces fixed request overhead but adds assembly delay and can delay urgent work. Presence checking wins only when its cost is smaller than avoided uploads: approximately `T_lookup < N_present·RTT + U_present/B` before overlap and batching corrections. Known parent references already avoid work and should not trigger redundant scans. Discover actual server capabilities, maximum batch bytes and supported encodings; upstream REAPI documentation is normative, while deployed support is an empirical question. ([Official REAPI](https://raw.githubusercontent.com/bazelbuild/remote-apis/main/build/bazel/remote/execution/v2/remote_execution.proto))

Preserve the order **required chunks stored → bundle stored → existing idempotent catalog commit**. Bound preparation concurrency and total bytes in flight, share existing time/byte/cancellation budgets, and handle partial batch failures per digest. Test cancellation, corrupt data, missing chunks, deadline exhaustion and restart. Stop if lookup/batching overhead consumes the benefit or publication is too small a critical-path fraction. Asynchronous publication after exit changes durability/completion semantics and is outside this first optimization.

The second P1 candidate targets `readCachedBytes`, `readCachedRange`, `blockDigest`, `FileSource.read/isCached` and `reuseRetainedChunk`. Current range reads allocate, open a channel, check sizes, read covering 4 KiB blocks and hash them; chunk lookup scans from the beginning. Retained activation verifies whole chunks and constructs block hashes each invocation. **Last-use mtime changes once at first retained reuse per session, not on every tiny read.** A full retained-cache hit can therefore avoid networking while still reading and hashing substantial local data. ([Read and activation implementation](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/RemoteSkyCache.java#L131-L500))

Select one intervention from profiles: indexed chunk offsets for repeated scans; bounded channel reuse for syscall cost; reusable buffers/digest instances for allocation; adjacent-read coalescing or immutable authenticated block caching for repeated reads. Measure each independently before combining. The approximately 790,700 shared-CAS gets justify investigation, not an assumption that every operation is redundant. If monitor contention dominates, compare sharded or less frequently updated metadata; with zero evictions, a larger cache is not the default remedy. Preserve authenticated returned bytes, size/mutation checks, cancellation and safe resource closure. A trusted in-memory copy can retain verified bytes; mtime, an open descriptor or a mutable mapping alone cannot replace authentication. Stop any candidate whose resource retention or synchronization costs erase the command-level gain.

## P2 should reduce useful-demand cost before adopting newer chunkers

Cold transfer deserves a separate experiment after attribution. Start with **fixed 1 MiB versus 256 KiB chunks**, replaying real demand traces before full builds. Measure distinct requested records, distinct fetched bytes, block-aligned bytes, repeat hashing, RPCs, encoded descriptor bytes, CPU and end-to-end latency. Test deterministic record-aligned packing by actual co-access only if traces show dispersed useful records. The peer-reviewed **PVLDB 2025 locality-aware graph-cache** study supports evaluating layout together with replacement; its Neo4j results do not forecast a SkyCache gain. ([Graph-locality study](https://www.vldb.org/pvldb/vol18/p2859-korkmaz.pdf))

An illustrative tradeoff for sparse demand and fixed total useful workload is `J(c) = a·c + b/c`: larger chunk size `c` increases overfetch, while smaller chunks increase request/index overhead. Positive coefficients `a` and `b` would need measurement; this is not an empirical fit to SkyCache. Its optimum `c* = sqrt(b/a)` applies only to that model; correlated access, finite records and bandwidth/latency change the tradeoff. Trace replay should replace the model's independence assumptions. Preserve whole-object digest authentication. A partial ByteStream range cannot be authenticated from the whole object's SHA-256 digest alone; smaller independently addressed objects preserve the current trust model without introducing a new proof protocol.

**Envelope feasibility precedes benchmarking.** V1 allows variable chunks up to 1 MiB, at most 32,768 references and a 1 MiB serialized bundle. The bundle cap can bind before the reference count. Aggressive 64 KiB chunks for the current 1.46 GB corpus can already make the envelope invalid; 4 GiB at 128 KiB reaches 32,768 references before encoding overhead. Measure actual serialized metadata and reject invalid variants. Manifest sharding is a separate protocol decision, not an implicit part of a chunk-size experiment. ([Protocol bounds](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/remote/SkyCacheProtocol.java))

The project's actual CDC evidence argues against prioritizing it: **108 real packs totaling 38,361,013 bytes yielded identical new-byte totals** for tested fixed and FastCDC variants. A synthetic insertion demonstrated resynchronization, not a real build benefit. The **9 October 2026 preprint** *Benchmarking Content-Defined Chunking Algorithms* changes how a future comparison should be run: isolate base algorithms from normalization/caching and compare **equal observed chunk sizes and distributions**, since nominal settings can produce misleading granularity differences. Its future ICDE 2027 acceptance is author-reported, not a completed 2027 publication. ([Project CDC evidence](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/skycache-remote-mvp.md#L974-L1014), [latest comparative preprint](https://arxiv.org/abs/2610.13704))

Only revisit CDC after realistic revision/compaction traces reveal boundary-shift savings. VectorCDC's **FAST 2025 paper and 2026 TOS extension** show that SIMD can reduce chunking CPU; faster boundary detection cannot create deduplication absent from the corpus. First inspect stable serialization and record ordering. Negotiated compression is another conditional experiment: approximate saved network time `(1−α)U/B` must exceed compression/decompression cost before accounting for overlap. Current upstream REAPI also documents optional streaming chunk-mapping interfaces; reconcile the vendored proto and server capabilities before considering them. These are future interoperability choices, not current SkyCache capabilities. ([VectorCDC research](https://arxiv.org/abs/2508.05797), [current REAPI specification](https://raw.githubusercontent.com/bazelbuild/remote-apis/main/build/bazel/remote/execution/v2/remote_execution.proto))

## P3 needs exact proof economics; WAN policy follows deployment evidence

**Exact ID representations and compact certificates are conditional P3 experiments.** The validator already memoizes successful roots, coordinates per root, defers shared in-flight dependencies and reuses witnesses within an invocation. Latest local rows contain 603,428 dependency records, 182,455 witness checks, 305,730 witness memo hits and 249,870 admission memo hits. Optimize remaining key allocation, lookup, capacity or cross-stage duplication only where observations have identical semantics and lifetime. Publication independently revalidates inputs and must retain that freshness boundary. ([Current validator](https://github.com/JSGette/bazel/blob/bf6b717195/src/main/java/com/google/devtools/build/lib/skyframe/serialization/local/LocalDependencyValidator.java#L124-L250), [counter evidence](https://github.com/JSGette/bazel/blob/bf6b717195/docs/jsgette/measurements/skycache-retained-chunks-agent-2026-10-25/comparison.json))

Compare publication-scoped canonical integer IDs and exact state arrays against existing objects only if profiles identify representation cost. Bind IDs to the dictionary, expected witness value and command epoch; hash collisions require full-key equality. The **SEA 2025 integer-index study** finds speed/space tradeoffs rather than universal superiority of compression: compressed Elias–Fano-style representations can save space while faster indexes win lookup time. Measure construction, decode, lookup and retained memory together. A certificate experiment must eliminate actual reads or graph expansion, not merely encode the same work differently. ([Primary indexing study](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SEA.2025.5))

The correctness invariant is: for entry `e`, compatible identity plus a **complete typed observation set** `W_e`, with every current observation equal to its expected value. Completeness includes dependency-discovery observations: nonexistent paths, directory membership and symlink resolution, alongside content, configuration, toolchains, external repositories and environment. **OSDI 2026 Incr** supports an explicit taxonomy of reusable, detectable and unsupported effects with conservative reruns. **ISSTA October 2026 DepReduce** supplies a useful model of objective-driven dependency optimization with preservation proofs; its declared-artifact transformations do not authorize deleting dynamic Skyframe witnesses. ([Incr](https://www.usenix.org/system/files/osdi26-xie-yizheng.pdf), [DepReduce](https://xuhongxu.com/issta26-depreduce.pdf), [Skyframe semantics](https://bazel.build/reference/skyframe))

A complete trusted change set `D` permits exact disjointness testing, `W_e ∩ D = ∅`. Git diff alone is incomplete for untracked/generated inputs, external state and missing-path creation. Without a trusted maintained summary, an exact first client must observe every relevant independent witness in the worst case: otherwise it cannot distinguish an unchanged workspace from one where only an unobserved witness changed. Certificates amortize work; they do not remove this information requirement. Avoid full transitive witness sets per entry, which can explode on shared DAGs. Preserve shared certificates and conservative fallback on incomplete coverage, dictionary changes or watcher overflow.

Test content edits preserving size/timestamps, deletion/rename, newly created paths, glob changes, symlink retargeting, configuration/toolchain/environment changes, external repository changes, corrupt certificates, epoch rollover, concurrent cancellation and ID reuse. Require identical verified outputs and conservative misses whenever evidence is incomplete. Probabilistic membership positives must never mean “validated clean”; advanced filters and reconciliation remain outside the initial sequence. Cost-aware early rejection is useful only if it adds to existing scheduling: prioritize cheap discriminating checks without changing the logical conjunction, and reject the optimization if positive hits regress.

Finally qualify deployment using independently initialized clients and linked worktrees, then independent clones only after stable repository identity is explicitly supported. Test measured LAN/WAN RTT, bandwidth and loss, plus multiple clients and eviction pressure. Tune separate network/read/publication concurrency and byte limits from queueing data; bandwidth-delay product is a starting estimate, not a command to raise concurrency. Preserve singleflight unless measured stripe collisions justify a bounded alternative. Cost-aware fallback can choose recomputation when expected lookup/validation cost exceeds expected savings, but must preserve outputs and existing miss behavior. Defer speculative prefetch, replacement-policy rewrites, hedging, learned policies and RDMA until their prerequisites and bottlenecks exist. Catalog retention, leases, authentication and capability negotiation are deployment gates, not demonstrated speedups.

## The first three experiments should settle the next investment

Run **first**, the same-binary consumption/publication split with overlap-aware profiling; **second**, bounded publication batches and presence checks, swapping order with reads if P0 identifies a larger opportunity; **third**, the single authenticated-read intervention selected by CPU/syscall/allocation traces. Each experiment keeps a current-behavior control, reports command-level and mechanism metrics, preserves the correctness contract and stops when its gain is too small or shifts cost into protected cases. Only then advance to valid smaller chunks/layout, and subsequently exact certificate economics.

The unresolved decisions are measurable: publication's critical-path share, unique demanded versus fetched bytes, retained authentication versus repeated-read costs, complete observation overlap, server batch capabilities, real WAN conditions and a defensible deployment identity. Resolving those variables turns recent algorithmic research into a focused optimization program. **The objective is lower verified build latency under explicit resource budgets.**
