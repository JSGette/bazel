# N1 Datadog trace coverage and overhead protocol

Prepared 2026-11-08, before any Datadog trace result. C-backed implementation and offline tests only: no launch, source change, or milestone verdict. Execute only after the reconstructed SkyCache candidate passes source/focused-test qualification and the real Java trace/replay smoke. Freeze this protocol, all manifests, helper hashes and order before the first measured result.

The question is whether this bounded observer captures useful real-workload evidence at a measured cost. It is not whether the leaf subset proves a shared evaluator can meet M4. The comparator is the **same newly qualified instrumented SkyCache binary with tracing disabled**, including its diagnostic `AtomicReference` branch. Do not compare trace-on costs directly with the historical `11547...` binary or the native-hosting binary. Both arms keep local SkyCache enabled.

## Finite cases and independent histories

Use the existing projected Datadog normalizer fixture at source revision `85ad968bca856fa3d4e07b4d8e11961dabe6866f`, target `//pkg/networkdevice/profile/profiledefinition/normalize_cmd:normalize_cmd`, scenario `identical`, one base/fastbuild worktree, and the existing independent normalizer behavior oracle. Preserve the projected archive hash, private Git tree, declared source/BUILD hashes, target and configuration. No source/configuration/glob edits belong to this initial overhead matrix; the smoke already tests small mutations.

There are **five fixed off/on pairs per lifecycle**, with separate restart and warm pools. This follows the frozen five-pair rule rather than selecting repetitions after seeing timing. Twenty fresh measured sessions each perform one trace-disabled preparation and one measured build: **40 builds total**, plus **one fresh correctness-only reference build**. The reference uses the same candidate, effective non-trace policy, source and seed, an independent output base/cache root, and tracing disabled; verify both exact executable digest and normalizer behavior. It is never a timing denominator.

Execute the reference first, then each table row's restart sessions followed by its warm sessions, all serially. Use `m1-trace-n1-reference-01` for the independent reference. Every session is a separate existing `run_auxiliary.ps1` invocation with a fresh run ID, owned scope, task-only reset and full-budget host preflight. Do not reset between preparation and measurement. Never reuse a failed root or import old M0/native references, output pools or SkyCache publications.

- **Restart:** prepare once with tracing disabled; verify output/behavior and the preparation daemon identity; shut down and prove that PID/start-tick identity absent. Start the measured command without a prior `info` command. Its JVM must be born after the request boundary and differ from the preparation JVM. Keep the successful preparation's named caches/output base.
- **Warm:** prepare once with tracing disabled; verify output/behavior and identity; issue the measured same-revision query without shutdown or intervening build. The measured JVM must retain exactly the preparation PID/start ticks. In particular, warm trace-on does not inherit a traced restart or a prior trace's allocations.
- **Both:** perform the same two identity queries after preparation, outside the measured request; bind measured output-base/PID to BEP and confirm identity after counters freeze. Keep successful pool histories explicit. No heap dump, forced GC, CPU/JFR profiler, JSON performance profile or extra warmup build is introduced.

The first off/on restart and warm pairs also establish real-target capture completeness. An invalid trace, observer overflow, output mismatch, accounting/ownership failure or infrastructure abort stops execution for assessment. Preserve the failed attempt; no automatic retry, larger limits or extra successful repetitions. A cause-based bounded repair requires a new recorded protocol/version; successful slow observations remain published rather than silently discarded.

It verifies source qualification, unchanged candidate bytes, successful Java tests, five actual archived Java smoke traces with their receipts/contexts, successful real replay and absent unsignalled scopes. No emitted runtime command contains a placeholder hash or infers success from a source tree. The reference precedes matrix emission; the twenty comparison manifests require its completed report, guard, successful independent archive-verification receipt and complete directory/type snapshot, including empty directories. The receipt binds the exact reference archive, report and manifest hashes; missing or failed verification blocks emission. Runtime rechecks those pinned inputs before using the reference oracle.

Each manifest pins the candidate path/SHA/bytes; full instrumented Git tree; base commit `a23ae68903f03f08ce83dcf1be85cdff54bb1eeb`; **literal combined base-to-instrumented patch SHA**; build/smoke report/proof hashes; fixture/seed/reference; exact helper/schema/replay hashes; run root; lifecycle/pair/order; resource/cache/temporary policy; literal launch prefix; and current host-guard proof paths. After writing the manifest, the emitter appends its actual SHA as the final CLI argument and writes the literal command JSON. The runtime derives that exact complete argv and command-file SHA from pinned prefix plus supplied manifest digest; it preserves the original manifest bytes separately from derived runtime fields. The wrapper resolves its own fresh scope/preflight at execution. This avoids pre-hashing future guard results and command/manifest self-references.

For on commands, construct context from the already-declared fixture and actual worktree, with unique engine/cohort/command-policy identities, `phase=restart|warm`, `hosting=private`, full candidate source identity, verified logical main-repository binding and actual physical root, filesystem policy, snapshot manifest SHA, and explicit Bzl-inlining state (unknown if not verified). The policy digest hashes the literal effective argument array, including the context **path**, not its future content. Record the SHA of raw context bytes immediately after writing and before launch. Recheck source/input binding and context after the command. External/generated repositories remain unsupported trace identities even though they are part of the build's full cost.

Use actual Java output only. Require unique trace/BEP UUIDs, exact header/context/BEP workspace/PID binding, complete footer and digest, frozen limits, and the matching real `TRACE.completion.json` after successful writer close. Preserve exact trace, receipt and context bytes. Off commands must produce no trace artifacts. Source/candidate/helper hashes and prior artifacts must stay unchanged.

## Cost windows and unresolved accounting

Record monotonic timestamps and raw counters for four explicitly named windows; none replaces another:

1. **Whole session:** start before fixture projection, seed copying or engine preparation; end after verification, owned shutdown and all request-owned cleanup. Include preparation and source ingestion costs here. Preserve preparation costs separately, including its compilation/repository bootstrap. This is a full lifecycle diagnostic.
2. **Prepared-root request through materialization and required drain:** start before reading/admitting the pinned request descriptor or producing its per-command context/command evidence. The revision bytes already admitted during preparation remain explicit pre-existing inputs. End after client response, requested output availability and verified required local publication completion. This is not edit-to-output or a qualified immutable-snapshot API; no changed-byte admission is being measured.
3. **Client build/response window:** bracket launch and an independent blocking wait for client exit. Freeze scope counters immediately at observed exit, before `info`, BEP parsing, output hashing, behavior oracle, trace parsing or archive copying. This remains comparable with earlier diagnostic boundaries, with their endpoint caveat.
4. **Post-response tail/drain and verification:** continue scope and memory observations from response. The local-only `LocalCacheSession.finish()` completes publication/seal/install and closes the session before `LocalSkycacheModule.afterCommand()` returns; the last trace module then finishes/writes its receipt before command return. Before each request, preserve and remove only the exact owned advisory `local-skycache-ownership.json` and `local-skycache.json` files; no cache publication is removed. Their recreation after the build, rather than mtime or unchanged old contents, proves freshness. Verify `after_session_close.session_closed=true`, no required pending validation, required publication success/no failure when applicable, receipt on traced commands, materialization and absence of transient request descendants. Do not require a new publication when no writes occurred. Keep a fixed 60-second deadline. An absent/ambiguous completion proof is **unknown/ineligible**, not a successful quiet-period heuristic; low CPU or a stable file list alone is not a queue-drain proof. Record subsequent oracle/source checks separately and in whole-session totals.

The existing native runner's `end_to_end` field is build plus its verification; it excludes fixture ingestion, final shutdown and parts of cleanup. Do not relabel that field as the frozen full boundary. The new runner must explicitly place the boundaries above, or mark the unavailable full-window metric unknown. Do not stop an expensive traced interval at BEP `BuildComplete`: LocalSkyCache finalization and whole-graph export occur afterward.

Reuse `m1_resources.ResourceSampler` for pinned cgroup and engine PID/start-tick observations. Primary cadence is 500 ms, with boundary reads, raw durations, exact membership and startup-pending coverage. Independently bracket **every scope CPU read** with whole-Python-process CPU before/after, including sampler/waiter/logging threads; reuse the conservative `harness_cpu_bounds` logic and preserve raw scope CPU. Known short-lived client/compiler descendants are included in whole-scope CPU even if absent from a process sample. Subtract only proven same-window observer bounds and proven compiler CPU; charge all remaining unknown work to build control. Negative, regressed or unresolved bounds stay unknown. BEP action user/sys time is supporting action evidence, not automatically a nonoverlapping substitute for process accounting; elapsed analysis/execution spans are never CPU.

Publish unique-daemon PSS, cgroup peak/current and anon/file/kernel memory, pressure/reclaim/throttling/OOM deltas, sample coverage and read cost. Current sampler PSS covers declared JVM engines; client/harness/other-service PSS and short-lived memory are not thereby complete. Report those uncovered roles explicitly, and do not label daemon PSS as total build-control peak. Full acceptance memory remains ineligible until those roles and boundary/drain coverage are measured. No forced GC or heap-payload-to-PSS conversion. Any scope/process ownership error, missing required accounting or OOM prevents performance eligibility.

## What the off/on comparison establishes

For each lifecycle and pair report raw on/off request/build/full-session CPU and wall, Python CPU bounds, conservative non-harness ratio `on_upper/off_lower` with a known positive denominator, daemon CPU with endpoint skew, sampled daemon PSS and cgroup memory/pressure, trace bytes/records/projections, and actual action/cache evidence. Publish all five pair ratios plus median/range; do not subtract the median tracing delta from individual traces or scale all function costs by an off/on ratio.

The collector synchronizes callbacks, retains bounded keys and versions, samples thread CPU, serializes JSON and walks the remaining graph at finish. It can change scheduling, caches, GC and worktree lifetime. Its callback work is inside some observed intervals. Trace-on CPU is therefore an **instrumented attribution envelope/potential**, not unperturbed evaluator cost, and the trace-off branch cost is present in both arms. Large overhead must remain visible even when outputs and receipts are correct.

The frozen **1.05 observer budget applies to 500-ms PSS versus endpoint-only sampling**, using its separately specified three pairs per system at N1 warm and N10 restart. It is not a pre-approved 5% tracing budget, and this off/on matrix does not perform or pass that observer qualification. Likewise the 1.10 N1 warm and 0.70 CPU/0.50 memory architecture gates are unchanged and do not apply as pass claims to these trace instrumentation controls. All results remain diagnostic until the relevant observer/full-boundary qualification is complete.

## Coverage, replay and the next decision

For each on trace publish actual nodes/functions, events versus retained-only/dependency-only nodes, complete/unknown grouped dependency observations, exact projection classes and roots, unsupported class/root reasons, captured versions, byte/count limits, and CPU capability/known exclusive state costs/unknown intervals. Metadata-backed/proxy regular files stay unsupported even when they expose a digest. BZL digests are input evidence only. Direct SkyCache witness validation, earlier cache setup, JIT/GC, virtual-thread work and missing retained nodes remain explicit gaps. Names can rank costly unknown families but cannot establish semantic equivalence.

After a session's accounting freezes and its owned scope exits, run the frozen replay on each actual trace individually, in a separate guarded postprocessing job. Keep per-trace inputs within the existing 256-MiB aggregate parser limit; do not silently raise it to combine repeated runs. Record parse and lookup/validation CPU/wall, Python traced allocation peaks, canonical payload/index/variant counts, source/contract/context/receipt hashes and any unavailable RSS. Python allocations/payload bytes are not Java retained heap or PSS. Repeated independent N1 captures are overhead/coverage observations, not a concurrent N2 sharing benchmark; do not turn repetitions into cross-engine avoided-CPU credit.

Only then decide whether N2 identical/distinct-snapshot captures are useful and fit the fixed budgets. Completion with material synchronous-trace overhead does not justify treating the attribution as unperturbed; assess or repair that observer before scaling. No N2/N10 launch is implied by this document. N1 alone supplies no semantic-sharing or M1 pass.

For the later M1 ceiling, preserve a generous upper bound for **all** potentially removable unsupported CPU/state in compatible windows; if it cannot be quantified, retain the whole unattributed envelope as possibly removable. Do not declare architectural impossibility because supported leaves are cheap, infer memory savings from projection bytes, or treat the old 44-MiB value payload as a ceiling on roughly 550-MiB per-process PSS. If unknowns dominate, select only the largest measured missing cost family for **one bounded investigation**, with its hypothesis/instrumentation/stop condition recorded before execution. If that does not resolve the savings ceiling, report M1 inconclusive and propose the appropriate pivot; do not keep expanding instrumentation families or soften the frozen 50%/30%/10% gates.

## Minimal implementation handoff

Prepared C-only helpers are `work/prepare_real_trace_n1.py`, `work/run_real_trace_n1.py`, `work/archive_real_trace_n1.py`, `work/run_real_trace_n1_matrix.ps1` and `work/test_real_trace_n1.py`. No live session or real candidate manifest has been emitted or launched. Existing frozen runners are not drop-in compatible: `m0_diagnostics.py` pins the historical binary/template and enables a CPU profiler; `native_comparison.Arm` uses native/private policy and only one measured lifecycle per run, with build-only accounting. They remain unchanged.

The emitter has separate `--role reference` and `--role matrix` modes; the latter requires explicit successful reference evidence. It emits `order.json`, fresh manifests and fully hashed literal command JSON, never starts a process. The runner owns one private session per auxiliary guard. It reuses the smoke's candidate/source/context validations; `fixture.prepare`, `oracle_inputs`, `verify_program`; `baseline.bep_metrics`; `native_comparison.audit_policy`, `bep_identity`, `scope_delta`, `harness_cpu_bounds`; and `m1_resources` through pinned imports. It does not call `native_comparison.run()`/`Arm` or monkey-patch their policy. No evaluator source changes are needed.

The sequential coordinator consumes the emitted fixed order, checks control/manifest/command hashes and never retries/resumes an existing row. Pins include the imported `analyze_native_n2.py` accounting validator; the verifier rechecks its own and that helper's bytes against the manifest before and after verification. `-DryRun` checks C-backed planned commands without WSL, guard import or workload launch. Real execution invokes the frozen auxiliary wrapper for one session, then the exact-path archive helper after its scope is verifiably absent. The helper caps each trace at 256 MiB, other selected members at 16/32 MiB, 128 members and the full uncompressed archive at 512 MiB; it preserves exact report bytes and per-member SHA256s. A missing runtime report receives an explicitly typed abort record, never a fabricated successful report. Runtime files remain preserved.

Off/reference rows receive C-only archived-accounting verification. Each on row receives a separate `-wire` auxiliary guard that reads only its C-backed archive, validates the actual trace/context/receipt/BEP linkage, and runs the frozen replay on exactly that one trace. Temporary extracted bytes are copies of hash-verified archive members, never synthesized trace data. It preserves the replay command, attestation, result and parser/allocation timings. An archive, guard, functional, accounting, completeness or real-wire failure stops the coordinator with persistent `execution-progress.json`; no later row launches. Full successful evidence remains diagnostic, with `performance_eligible=false` and no milestone verdict.

Invocation sequence, only after real source/smoke qualification: run `prepare_real_trace_n1.py --role reference` with explicit archived build/smoke directories, literal read-only source-repository path and a fresh C-backed destination; dry-run and then execute `run_real_trace_n1_matrix.ps1 -OrderJson <that destination>/order.json`. After its archived reference passes, run the emitter with `--role matrix --reference-evidence <explicit reference evidence directory>` into a new destination, then dry-run/execute that order. The emitter requires actual proof, never accepts a placeholder candidate, and refuses missing or inconsistent archived Java smoke evidence.

Before execution, offline tests must reject missing/changed build or smoke proof, wrong lifecycle history, same preparation/restarted identity, changed warm identity, mixed paired policy/caches, mutated raw context, omitted required completion, failed/ambiguous drain, incomplete counter bounds and unknown PSS mislabelled as zero. Literal command generation must be dry-run checked without WSL/process launch. Archive every result or abort, exact commands, fixture/seed policy, guard/preflight/cleanup proof and unknowns; no automatic retries or gate verdicts.
