# Skyframe ownership and replacement choices

Scope: source inspection of `JSGette/bazel` branch `jsgette/native-multi-worktree-mvp`, pinned at `4f4b44b5a2c1780cdbb0215c4556de39d0f0a995`, plus official Bazel documentation retrieved 31 October 2026. No builds, tests, benchmarks or source modifications were performed by this researcher. The new interfaces and staged decisions below are proposals, not implemented capabilities.

## Is Skyframe itself the obstacle, or are identity and ownership the obstacle?

### Takeaway

Keep separate Skyframe evaluators in the first new MVP. A common live graph requires changes to node representation, versioning, evaluation and Bazel ownership; replacing the evaluator alone does not fix workspace-sensitive inputs, path-bearing values, callbacks or action side effects. The abstract version API is broader than the current implementation, so a multi-version Skyframe backend is an alternative to replacing all of Skyframe.

### Cited Findings

- Current `InMemoryMemoizingEvaluator` explicitly disallows concurrent evaluation and graph access alongside evaluation, and uses monotonic integer versions for incremental builds. The implementation has one differencer, dirty/deletion/injection sets, emitted-event state, last version, and an atomic reentrancy guard. Cancellation cleanup deletes unfinished nodes and their reverse dependencies. [Evaluator contract](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/InMemoryMemoizingEvaluator.java#L25-L34), [state and evaluation](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/AbstractInMemoryMemoizingEvaluator.java#L67-L196), [reentrancy guard](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/AbstractInMemoryMemoizingEvaluator.java#L231-L234).
- `IncrementalInMemoryNodeEntry` holds a mutable node version, direct dependencies, reverse dependencies and dirty/building state. The parallel evaluator depends on coordinated queue, node and in-flight state; interruption removes incomplete work. Internal parallelism is therefore not concurrent independent commands against the same graph. [Node representation](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/IncrementalInMemoryNodeEntry.java#L35-L84), [scheduler invariants](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/AbstractParallelEvaluator.java#L70-L104).
- `Version` describes a partial order and explicitly permits incomparable versions. This is evidence of conceptual headroom, not evidence that the current evaluator already supports forked worktree histories. [Version interface](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/Version.java#L18-L48).
- `ConfiguredTargetKey` includes label, configuration and optional execution-platform/transition distinctions, but not the source snapshot of a worktree. Equal keys across engines can legitimately produce different configured targets. Configured-target values are also destructively clearable, despite Skyframe's conceptual immutable-value model. [Key identity](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/ConfiguredTargetKey.java#L45-L123), [value clearing](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/AbstractConfiguredTargetValue.java#L25-L63).
- Artifact factories retain physical roots and source artifact caches. Action executors retain invocation-dependent client environment, action maps and reporting state. Consequently even a perfectly versioned graph cannot make arbitrary Bazel values portable by itself. [Artifact factory](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/actions/ArtifactFactory.java#L49-L81), [action executor state](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/SkyframeActionExecutor.java#L199-L253).
- Graph-backed global key/label pools are installed by graph construction; the branch disables this pooling for multiple graphs. This is a concrete example of an ownership optimization rather than an intrinsic limitation of incremental evaluation. [Pool construction](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/skyframe/InMemoryGraphImpl.java#L95-L103), [branch backlog R6](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/docs/jsgette/plans/multi-worktree-completion-roadmap.md).
- Skyframe requires dependency reads to be registered; invalidation propagates through reverse dependencies and supports change pruning. File existence, symlinks and directory listings participate, not only file content digests. [Official Skyframe model](https://bazel.build/reference/skyframe).

### Inferences

**The design should name four different identities.** These are proposed concepts:

1. `EngineGeneration`: a worktree/output owner whose generation changes when drained and reopened. It protects handles and callbacks; it is not a content hash.
2. `ObservationEpoch`: one engine's view of filesystem/configuration inputs and invalidation state. An integer from A must never be compared as if it were B's source version. Initially preserve ordinary Bazel filesystem semantics rather than claiming an immutable filesystem snapshot.
3. `SemanticRequest`: function implementation/version plus all inputs actually required by a deliberately pure stage. A full-workspace snapshot in every key is safe only under a real snapshot contract and defeats reuse after unrelated edits. A Git commit excludes dirty/untracked inputs and is not such a contract.
4. `PayloadId`: verified immutable bytes or structural immutable content. Sharing this is independent from ownership of graph nodes or outputs.

**Ownership interface proposal.** Daemon owns admission, registry, immutable stores, action coordination and shared metrics. `EngineHandle(generation)` owns runtime, evaluator, differencer, repositories, artifacts/output namespaces and command serialization. `InvocationLease(engineGeneration, cancellation, reporter, resourceLease)` owns command work and callbacks. Teardown first closes admission, then drains all invocation/background leases, then disposes engine resources and removes registries, then releases output reservations. A stale callback must fail a generation check; carrying only a thread-local identifier is insufficient for asynchronous continuations. Cache leases pin immutable payloads but cannot grant write access to an output root.

**Immediate scope recommendation:** make the next implementation MVP a recyclable engine lifecycle with a bounded retained-engine policy, retaining two active engines and existing feature restrictions. Do not combine this with an experimental portable compiler, shared graph, new scheduler and remote execution. Benchmark that corrected substrate next. Resource accounting can initially expose and enforce admission limits without promising hard per-engine heap isolation, which one JVM cannot provide. The parent branch audit supplies concrete registry-retention and construction-lock evidence supporting this priority.

**A later multi-version graph can be narrower than a full rewrite.** Prototype a versioned immutable node-record store with session-local dirty/in-flight/reverse-edge overlays behind a graph abstraction; retain SkyFunction semantics initially. Its difficult part is proving dependencies and context-free values, not choosing a concurrent map. A new scheduler/backend must support dependency grouping/order, dynamic dependencies, cycles/errors, change pruning, rewinding, cancellation and reclamation. Replacing all SkyFunctions and rule execution as well is the highest-risk option and has no evidence-based justification yet.

### Gaps

- No retained-heap attribution proves how much cost lies in graph bookkeeping versus syntax, modules, configured targets, actions, roots or JVM overhead. Node-count duplication alone does not choose a rewrite.
- No complete ownership/global-state audit was performed here. The architecture cannot promise isolation from JVM crashes, stop-the-world GC or native process-global state.
- No immutable-worktree filesystem snapshot provider is present in the audited design. Atomic snapshot consistency is a new product contract requiring either actual snapshots or documented validation/retry behavior.

## What exactly can be reused first, and what makes a reuse proof valid?

### Takeaway

The useful next computation boundary is source acquisition followed by pure Starlark parse/resolve, but the current `Program` cannot simply be cached by source digest and shared across worktrees. Physical locations, guarded symbol visibility and post-compile type-tagging mutations must be addressed. Treat this as a separate, tightly bounded prototype after the lifecycle MVP, with an explicit stop if location or immutability changes become a compiler rewrite.

### Cited Findings

- `BzlCompileFunction` obtains semantics and `FileValue`, handles missing/special files, reads bytes, derives a digest and physical filename, chooses dialect/type options and the predeclared environment, then parses and compiles. The line immediately before parsing is an existing acquisition/computation seam, but size-policy diagnostics and context-sensitive resolution are interleaved with it. [Acquisition](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlCompileFunction.java#L109-L235), [parse/compile seam](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlCompileFunction.java#L237-L307).
- `Program.compileFile` mutates the AST to resolve identifiers and locals and accumulate errors. This alone does not prove a completed untyped program is unsafe: mutation during construction may be compatible with later freezing. However, `Program` retains the syntax-derived function body, load locations and documentation nodes, and `getFilename` returns the body's location filename. [Program representation](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/syntax/Program.java#L24-L105), [compile mutation contract](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/syntax/Program.java#L132-L185).
- There is a concrete **post-compilation mutation path**. `BzlLoadFunction` calls `Starlark.withTypeInfo` after loading dependency modules. That tags the existing program; `TypeTagger.visit(CastExpression)` writes the resolved cast type into its AST node. The returned `Program.withTypeTable` copies the wrapper while retaining the same body. A completed compiled program is therefore not automatically a deeply immutable reusable payload for typed execution. [Load-time typing](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlLoadFunction.java#L875-L889), [typing call](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/eval/Starlark.java#L1371-L1381), [cast mutation](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/syntax/TypeTagger.java#L681-L685), [shallow wrapper](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/syntax/Program.java#L61-L70).
- Every syntax node contains `FileLocations`; location methods consult that object's file name. A wrapper around `Program` cannot rebase all nested locations. Runtime errors, load visibility errors, documentation and module context are among the observable uses. [Syntax location ownership](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/syntax/Node.java#L64-L89), [module/load context](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlLoadFunction.java#L823-L914).
- Resolution depends on predeclared symbol availability, semantics and client data through guarded values, not just syntax. `Module.resolve` distinguishes global/predeclared/universal symbols and can return context-dependent access errors. [Module environment](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/eval/Module.java#L93-L108), [resolution](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/net/starlark/java/eval/Module.java#L265-L298).
- `BzlLoadFunction` additionally resolves loads through repository mappings, obtains dependent modules, calculates transitive digests, constructs context containing the label, mapping, filename and load DAG, and executes with mutable module/thread context. These are separate from a compilation payload. [Load dependencies](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlLoadFunction.java#L773-L860), [local module and execution](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/BzlLoadFunction.java#L862-L914).

### Inferences

**Smallest safe extraction:** first refactor acquisition without changing behavior. `AcquireCompileInput` remains engine-local and requests the same Skyframe dependencies. It returns owned immutable bytes and explicit options; local code retains source observations, physical location, size limits/listeners, error publication and lifecycle. `CompilePure` must not receive `Environment`, reporter, filesystem, engine, artifact factory or callback closures. A `CompileResult` is published only when complete. No in-flight compilation coalescing initially: duplicate misses are acceptable and much simpler than shared cancellation.

**Conservative exact-key prototype:** immutable bytes/content digest with length and digest-function identity; compiler implementation/schema identity; compile kind/dialect and all `FileOptions`; full `StarlarkSemantics` initially; logical label/client access context; an explicit immutable description of resolver-visible names/scopes/guard decisions; physical filename until all location uses are separated. Policy and errors remain local, or are stored as immutable structured diagnostics with caller-specific rendering. A producer must hash the actual bytes it compiles; do not assume an earlier file observation is an atomic content snapshot. Prefer over-keying until measured evidence justifies trimming. Never key on Java object identity or only a module digest.

This first extraction/exact-path cache is a **correctness seam**, not a claim of worktree reuse. Different physical paths will miss, and that is the honest result. It can be tested without broad graph changes. An untyped subset may become shareable after a complete post-publication mutation audit; typed paths must remain private until their mutable annotations are separated or copied. No negative/error caching in the first cache reduces diagnostic/retry complications.

**Portable next prototype:** use a content-addressed frozen syntax or executable payload containing source offsets, immutable bindings and immutable instructions, with per-engine `SourceBinding` and mutable typing/module state. This is a proposed representation, not an available `Program` facility; current `Program` is AST-based, not a ready portable bytecode blob. Evaluate either (a) local AST instantiation from a frozen parse/compile template, retaining existing APIs at copying cost, or (b) location/typing indirection throughout consumers, with greater refactoring cost. A template that copies the whole AST might save parse CPU yet save no retained heap and may use more memory; measure it. Stop if no narrowly auditable portable slice exists. Do not silently substitute path-string rewriting for correct source binding, and do not bundle a new VM into the first MVP.

**If later reusing whole evaluations, record an observation receipt.** Proposed receipt: function/schema identity; semantic request; ordered dependency groups; each observed semantic dependency key and value identity; missing-path observations; directory membership/glob results; symlink resolution; repository mapping and external-repository state; configuration/toolchain/predeclared/environment observations; structured error/event policy; immutable result identity. Before reuse, validate the receipt against the *requester's* consistent input view and register dependencies in that requester's graph. Abort/recompute on any mismatch, missing observation, non-hermetic read, or unsupported side effect. A prior trace is not a certificate simply because its positive file digests match. Validation of earlier branch-controlling observations must precede stale downstream requests, preserving dynamic dependency semantics. This is substantially more work than pure compilation reuse and should not enter its MVP.

**Cache and GC contract:** cap cache-owned entries and retained bytes; eviction drops the cache reference while live consumers retain immutable payload handles. Also report pinned bytes and total engine memory: a cache capacity does not bound payloads reachable from live graphs. No shared payload may retain an engine or callback closure. Private graph wrappers retain reverse dependencies, dirtiness, errors/events and release behavior. Share immutable repository download bytes through an audited cache, not a writable repository directory or its owner-specific lock state.

### Gaps

- No complete mutation audit establishes that all untyped completed programs can be concurrently executed safely. The typed mutation is a demonstrated hazard, not an assertion that every execution mutates every program.
- No performance evidence establishes that copying a frozen template is cheaper than parsing or that portable compilation beats lower-risk payload interning. This must be measured before committing to broad syntax representation changes.
- The exact semantic compile key is a proof obligation. The conservative list above is a design starting point; an environment-schema implementation and caller audit must demonstrate its completeness.

## Can serialization or a new backend avoid a full replacement, and when should replacement proceed?

### Takeaway

Existing serialization is the first infrastructure to evaluate for portable stored bytes and eviction/reload, but it is not a ready shared live graph. Proceed toward a new graph/backend only after equal-semantics benchmarks locate a material cost in structures it can remove and a small differential prototype demonstrates correct independent invalidation. Do not use duplicated node counts or cache hit rate as the decision criterion.

### Cited Findings

- `FrontierNodeVersion` includes the top-level configuration checksum because output paths can depend on the transition from that top-level configuration; it also includes Bazel installation hash, Starlark semantics, source evaluating-version and fake-stamp status. Its remote snapshot/client pointer is explicitly excluded from cache hash/equality and is used to retrieve associated invalidation metadata. This is richer than a label/configuration key, and its version has external semantics that cannot be replaced by independently incremented local counters. [Version fields and rationale](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/serialization/FrontierNodeVersion.java#L43-L116).
- Shared deserialization uses a fingerprint plus an optional distinguisher to coordinate retrieval. Reusing bytes and reusing decoded objects are distinct decisions. [Shared deserialization](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/serialization/SharedValueDeserializationContext.java#L328-L364).
- When remote analysis caching is disabled after use, `SkyframeExecutor` deletes relevant deserialized values because those nodes lack the transitive edges back to file/directory nodes. The external invalidation path is therefore part of correctness, not optional performance plumbing. [Deserialized-node invalidation](https://github.com/JSGette/bazel/blob/4f4b44b5a2c1780cdbb0215c4556de39d0f0a995/src/main/java/com/google/devtools/build/lib/skyframe/SkyframeExecutor.java#L597-L632).
- Action caching already separates action-result metadata from immutable output blobs. It can share reproducible output content without sharing writable execroots or graph state. [Official remote caching model](https://bazel.build/remote/caching). Ordinary Bazel servers retain graphs and serialize invocations by output base; this remains the independent-process control. [Official client/server model](https://bazel.build/run/client-server).
- Discarding analysis or graph edges reduces memory by sacrificing future incremental work; preserving action-cache hits does not preserve loading/analysis performance. [Official memory tradeoffs](https://bazel.build/advanced/performance/memory).

### Inferences

**Experiments in increasing scope:**

1. Lifecycle-correct private engines, current payload/action sharing, independently switchable sharing controls. Benchmark against isolated conventional servers under equal total resources.
2. Pure compile boundary and bounded completed cache; conservative identity first, portable payload only after path/mutation proof. Benchmark parser/resolver CPU avoided, allocation and retained heap, plus total build time.
3. Audited serialized analysis subset with private decode/context rebinding. Reuse codec/byte-store infrastructure if feasible; do not assume a deployed invalidation service or context-safe global decode map exists. Measure serialization, transfer, decode, validation and local wrapper overhead.
4. One multi-version graph slice, preferably a side-effect-free loading computation with negative lookups and divergent/reconvergent edits. Keep output/action ownership local. Compare immutable records plus overlays against isolated graphs; demonstrate that shared records are actually retained once.
5. Only then choose extension versus replacement of evaluator/storage. A backend replacement can retain much Bazel semantics, while a clean-sheet engine must re-prove them.

**Replacement gates, to set before implementation rather than after seeing attractive numbers:** a representative target/worktree matrix shows remaining duplicated graph/analysis state is the material bottleneck; conservative payload/serialization approaches fail agreed latency/memory goals; a prototype new backend materially improves end-to-end metrics under the same supported semantics and total resources; correctness equivalence holds under edits, restoration, cycles, failures, cancellation, source races and cleanup; retention remains bounded over churn; compatibility and migration effort fit the intended release scope. Thresholds should be agreed against the user's memory/latency/concurrency priority; no universal percentage is justified by current data.

**Differential proof:** compare outputs and exit codes with isolated ordinary Bazel controls; compare target/action graphs where meaningful; account for expected path differences explicitly rather than normalizing arbitrary diagnostics. Include dirty and untracked files, source/BUILD/.bzl changes, absent-to-present paths, glob membership, symlink retargeting, repo/module mappings, local repository edits, option/environment/toolchain changes, and A/B divergence then convergence. Add forced cancellation at acquisition/publication/materialization and engine close while B is live. An invalid reuse should fail closed to local recomputation. A snapshot/graph experiment should run in shadow or compare mode before serving reused results.

**Benchmarks next, polish last:** correctness tests and basic instrumentation belong in the MVP; performance qualification is the next stage. Fair scheduling, sophisticated in-flight compile sharing, remote interoperability, new platform support, broad command coverage, profiling restoration and full release ergonomics follow measured selection, not the first prototype. A failed benchmark is useful evidence to abandon the extra sharing layer.

### Gaps

- Existing serialization source does not establish accessible remote service deployment or a turnkey local cross-worktree analysis cache.
- No comparative benchmark was executed in this research. Benefits of versioned graphs, compiler sharing or replacement are hypotheses, not performance claims.
- Replacement remains an option, not a conclusion: current evidence establishes coupling and duplication, but not that replacement gives better cost/benefit than targeted ownership and immutable-payload work.
